# SAP Content Repository Interface Research: Connecting an External SharePoint (Graph) Adapter to SAP S/4HANA 2025 Private Cloud (RISE)

Status: desk research, 2026-10-08. Sources are public web pages. Paywalled SAP Notes and the full SAP partner specifications could not be read. Items marked **UNVERIFIED** are based on general SAP knowledge or secondary sources and must be checked on the customer system or in SAP for Me.

## 0. Target release

- SAP S/4HANA 2025 (on-premise and Cloud Private Edition / RISE) runs on **ABAP Platform 2025**. The SAP_BASIS component is **816**. SAP security advisories from 2025 list SAP_BASIS 816 among the supported versions, and SAP published an "ABAP Platform in SAP S/4HANA Cloud Private Edition and SAP S/4HANA 2025" highlights deck. ## 1. SAP Content Server HTTP Interface (ArchiveLink / KPro "HTTP content server")

### 1.1 Supported in S/4HANA 2025?
Yes, with high confidence. The HTTP Content Server interface is the protocol behind:
- OAC0 storage type **"HTTP content server"**, used by Knowledge Provider (KPro) consumers: DMS originals (CV01N/CV02N through storage categories), GOS "Store business document", and the Fiori Attachment Service when it uses DMS or KPro storage.
- **ArchiveLink** (OAC0 repository with an ArchiveLink protocol from OAA3, version 0045/0046/0047), used by GOS ArchiveLink attachments, incoming document scanning, outgoing print lists and data archiving (SARA) file storage.

Vendors still certify against it for S/4HANA. Examples are Doxis4 HCS 07.04 (certified scenario **BC-AL 7.40**), Gimmal ERP-Link and KGS. Partner products listed on sap.com describe "ArchiveLink over HTTP/S" as an option for RISE. (Sources 4, 5, 6, 12)

### 1.2 Versions
| pVersion | Name | Notes |
|---|---|---|
| 0045 | HTTP Content Server 4.5 | Baseline spec. Public SAP Help page: "SAP Content Server HTTP 4.5 Interface" (Source 7). Normally sufficient. |
| 0046 | 4.6 | Adds cache-server / extended-function support. An SAP KBA says to use 0046 when a cache server is involved (Source 8). |
| 0047 | 4.7 | Latest version. A KBA says 0047 is not selectable in OAA3 on some older Basis releases (Source 8). The function deltas compared with 0046 are **UNVERIFIED**; the full 4.7 spec is distributed to ICC partners and is not public. |

There is no "4.8". No public reference to a version newer than 0047 was found.

Recommendation: implement 0045 semantics fully and accept `pVersion=0045|0046|0047`. Echo the requested version in `X-pVersion` where appropriate.

### 1.3 Function commands
Every request has the form `http(s)://host:port/<path>?<command>&pVersion=..&contRep=..&...`. The command is the first query token, which has no value.

| Command | HTTP method | Purpose | accessMode |
|---|---|---|---|
| `serverInfo` | GET | Server and repository status | (none, or r) |
| `info` | GET/HEAD | Document and component metadata | r |
| `get` | GET | Component content, or a byte range (`fromOffset`/`toOffset`) | r |
| `docGet` | GET | Whole document, all components as multipart | r |
| `create` | PUT (single component, body = content) or POST (multipart/form-data, one part per component) | Create a document | c |
| `mCreate` | POST multipart | Create several documents | c |
| `append` | PUT | Append data to an existing component (print lists) | u |
| `update` | PUT/POST | Replace or add components | u |
| `delete` | GET/DELETE | Delete a document or one component | d |
| `search` | GET | Full-text search in a component (print lists) | r |
| `attrSearch` | GET | Attribute search (print-list index) | r |
| `putCert` | PUT | SAP sends its public certificate for signature checking | (none) |

The command list is confirmed by Sources 7, 9 and 10. The exact HTTP method allowed per command (for example DELETE versus GET for `delete`) is **UNVERIFIED** in detail. Be lenient and accept both.

### 1.4 URL parameters
- `contRep`: 2-character repository ID from OAC0. Mandatory.
- `docId`: document ID generated by SAP, 32 or 40 characters. Mandatory for document operations.
- `compId`: component ID, for example `data` or `data1`, or the KPro file names used by DMS and GOS. Optional or mandatory depending on the command.
- `pVersion`: 0045, 0046 or 0047.
- `accessMode`: a combination of `r`, `c`, `u` and `d`.
- `authId`: certificate owner ID, for example `CN=<SID>`, identifying which stored certificate verifies the signature.
- `expiration`: `YYYYMMDDHHMMSS` in UTC. Reject the request when this time has passed.
- `secKey`: URL-encoded base64 signature.
- Optional: `fromOffset`, `toOffset`, `docProt`, `Content-Type`, `charset`, `version`, `resultAs` (`ascii`/`html` for serverInfo and info), `pattern`, `caseSensitive`, `numResults` (search).

### 1.5 secKey / signed URLs
- SAP signs the parameter values in a fixed order: `contRep`, `docId`, `compId`, `accessMode`, `authId`, `expiration`, concatenated without separators. The signature uses the system's private key (System PSE in STRUST). The result is **PKCS#7 signedData**, base64-encoded and then URL-encoded. (Sources 9, 10.) The KGS description lists contRep, docId, compId, accessMode and expiration. Whether authId is part of the signed string is **UNVERIFIED** and must be tested. The legacy algorithm is **DSA with SHA-1**. Newer systems can use RSA/SHA-256 depending on the PSE. **UNVERIFIED**, so support both.
- **putCert**: In OAC0 the administrator presses "Send certificate". SAP then issues `PUT ...?putCert&pVersion=..&contRep=XX&authId=CN=SID&expiration=...` with the certificate in the body. The server stores the certificate per contRep and authId. It stays **inactive** until an administrator activates it on the content server side. For SAP's own Content Server this happens in CSADMIN ("Certificates" tab). A third-party server needs its own admin UI or CLI for this step.
- Per repository the server should support three modes: no signature check (OAC0 "no signature"), signature required for all commands, and signature required only for certain accessModes.
- Signed URLs are also handed to SAP GUI and browser frontends for direct display. This means the adapter's endpoint must be reachable from end-user clients as well as from the ABAP server, unless the repository is configured for back-end/proxy access. Check the OAC0 "HTTP/HTTPS front end/back end" settings. **UNVERIFIED for Fiori attachment flows.**

### 1.6 Responses
- `info` / `docGet` document-level headers: `X-dateC`, `X-timeC`, `X-dateM`, `X-timeM`, `X-contRep`, `X-numberComps`, `X-docId`, `X-docStatus` (`online`/`offline`), `X-pVersion`, `X-ContentServer` (Source 11).
- Per component (multipart part headers): `X-compId`, `X-Content-Length`, `Content-Type` (with charset), `X-compDateC`, `X-compTimeC`, `X-compDateM`, `X-compTimeM`, `X-compStatus`, `X-pVersion`.
- On upload, SAP sends `X-compId`, `Content-Type` and `Content-Length` per part. Content-Length must be byte-exact (Source 11).
- Status codes: `200` OK, `201` Created, `400` bad request, `401` signature or security error, `403` forbidden, `404` document or component not found, `409` conflict (document already exists on create), `500` internal error. Return an error description in the `X-ErrorDescription` header. The header name is **UNVERIFIED** and should be checked against the spec.

### 1.7 Minimum implementer scope
| Scenario | Required commands |
|---|---|
| DMS (CV01N/CV02N originals via KPro) | serverInfo, info, get, docGet, create (PUT and POST multipart), update, delete, putCert, secKey checking |
| GOS attachments / Fiori Attachment Service (KPro based) | Same as DMS |
| ArchiveLink (scanning, outgoing docs, GOS ArchiveLink links) | Above, plus mCreate and range `get` |
| Print lists / SARA archive files | append, search, attrSearch, range `get` |

Mapping to SharePoint: contRep maps to a site or library, docId to a folder (or a list item with metadata), and compId to a file. Use Graph upload sessions for files larger than 4 MB. Keep a metadata index of timestamps and status so that `info` can be answered without slow Graph traversals.

## 2. CMIS repositories in S/4HANA

- OAC0 offers a storage type **"CMIS content repository"** (shown as "CMIS Content Server" in some vendor docs). It uses an SM59 **type G** destination to the CMIS endpoint and the ABAP CMIS client. Configuration guides from Alfresco, T-Systems ImageMaster and SAP community blogs describe this setup. (Sources 13, 14, 15)
- **Binding**: the ABAP integration with SAP BTP Document Management service uses the CMIS 1.1 **Browser binding** (JSON, `/browser` path). Whether OAC0 CMIS repositories can also use AtomPub is **UNVERIFIED**. Plan for the Browser binding.
- **Scope**: CMIS repositories are KPro repositories. They work for the Attachment Service, GOS through KPro, and DMS. SAP Note **3094622** is cited as a prerequisite for external CMIS repositories with the attachment service (Source 16). Older storage types and KPro storage types cannot be mixed. **ArchiveLink over a CMIS repository is not supported** for the classic ArchiveLink protocol on-premise or Private Cloud: **UNVERIFIED**, ask SAP. In S/4HANA Cloud Public Edition, CMIS is the only option and ArchiveLink is not supported there (Sources 16, 17).
- **SAP BTP Document Management Service (DMS)** is CMIS-based. It can act as the content server for S/4HANA, and it can onboard *external* CMIS-compliant repositories (Sources 18, 19).
- **Important for this project:** SharePoint Online has **no CMIS endpoint**. CMIS was only ever available in SharePoint Server on-premises (Source 20). A CMIS route therefore still requires the adapter to implement a CMIS 1.1 Browser-binding server facade over Graph. That is considerably more work than the HTTP Content Server protocol: object model, type definitions, query, ACLs and versioning.

## 3. RISE / Private Cloud considerations

- **No platform ban on external content servers.** Vendors market both ArchiveLink/HTTP and CMIS repositories for RISE Private Cloud. The archive runs outside the SAP tenant and is reached over defined networks (Sources 12, 21).
- **Certification**: SAP ICC certification (scenario **BC-AL** / ArchiveLink, historically "BC-HCS" for the HTTP content server, current versions such as "BC-AL 7.40") is **not technically required** for SAP to call the endpoint. It matters commercially and for SAP support: SAP Support may decline incidents involving uncertified servers. Whether RISE/ECS requires certification for externally connected content servers is **UNVERIFIED**. Certification enquiries go to icc@sap.com (Sources 4, 5).
- **Connectivity**:
  - OAC0 points to a host and port, or an SM59 type G destination for CMIS. For HTTP Content Server, set the host, port, SSL port and path prefix in OAC0. HTTPS needs the server CA imported into the SSL client PSE in STRUST.
  - The RISE tenant usually reaches the customer network over site-to-site VPN, Azure ExpressRoute or Private Link/peering. Outbound access to a customer IP and port needs an **ECS firewall / network service request**, plus allowlisting on the customer side.
  - Because of the front-end URL behavior described in 1.5, SAP GUI and browser users may also need direct HTTPS reach to the adapter, so internal DNS and certificates matter.
  - A proxy can be configured in SM59 or in OAC0 global settings. **UNVERIFIED** for the specific tenant.
- No SAP-side installation is needed. This is clean-core friendly because there is no add-on on the stack.

## 5. Recommendation

**Implement the SAP Content Server HTTP Interface first** (pVersion 0045, also accepting 0046 and 0047) with full secKey/putCert support. **Confidence: high (about 85%).**

Rationale:
1. It is the only protocol that covers all four scenarios: DMS, GOS, ArchiveLink and the Fiori attachment reuse component through KPro/DMS.
2. It is fully supported on ABAP Platform 2025 / S/4HANA 2025 Private Cloud and needs nothing installed on SAP.
3. It is the protocol the established SharePoint vendors implement and certify.
4. It maps simply onto Graph operations.

Treat CMIS (Browser binding) as a **phase-2 option** (confidence medium, about 60%). It is the direction SAP is taking for clean core and Public Cloud, but it does not cover ArchiveLink and it needs a large server facade because SharePoint Online has no CMIS.

### Checklist for the customer's Basis team
1. Confirm the release and support pack: S/4HANA 2025 FPS, SAP_BASIS 816 SP.
2. In **OAC0**, check which storage types are offered ("HTTP content server", "CMIS content repository") and whether new repositories can be created in the tenant.
3. In **OAA3**, check that ArchiveLink protocol version 0047 (or 0046) is selectable.
4. In **STRUST**, check the System PSE algorithm (DSA versus RSA) used for secKey, and import the adapter's TLS CA into the SSL client PSE.
5. Check the **DMS** setup: document types (DC10), storage categories (OACT/CV settings), and whether the Fiori Attachment Service is configured to use DMS. Review SAP Note 3094622 and related attachment-service and CMIS notes.
6. Check **GOS** settings (SGOSATTR, the KPro category for attachments) and the ArchiveLink links (OAC3) to be redirected to the new repository.
7. Raise an **ECS network service request** for outbound HTTPS from the RISE VNet to the adapter (IP, port, FQDN), and confirm that SAP GUI and browser clients can reach the adapter URL.
8. Decide whether to pursue SAP ICC certification (BC-AL) for supportability.
9. Search SAP for Me for the current Content Server and ArchiveLink notes for SAP_BASIS 816, and for any RISE content-server policy. **UNVERIFIED**: no specific note number was confirmed beyond 3094622 and the KBAs referenced below.
